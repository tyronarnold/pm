# Frontend

Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript 6.0. Drag and drop uses `@dnd-kit`. Built as a static export (`output: "export"` writes to `out/`), which the Docker image copies into the backend and FastAPI serves at `/`. Boards are loaded from and saved to the backend (`/api/boards`).

## Commands

```
npm run dev          dev server on http://localhost:3000 (no backend, so sign-in does not work there; use the container)
npm run build        static export to out/
npm run lint         eslint (ESLint 10; `overrides` in package.json let eslint-config-next's react, import and jsx-a11y plugins accept it, since their latest releases still declare an ESLint 9 peer. The rules Next enables work; eslint-plugin-react's `forward-ref-uses-ref` and `jsx-filename-extension` crash on ESLint 10, so do not enable them. Remove the overrides once those plugins support ESLint 10)
npm run api:types    regenerate backend/openapi.json and src/lib/api-types.ts after changing backend models (needs Docker; downloads openapi-typescript 7.13.0 with npx, kept out of the dependencies because it declares a TypeScript 5 peer)
npm run test:unit    vitest (jsdom)
npm run test:e2e     playwright; builds the image and runs a throwaway `pm-test` container on http://127.0.0.1:8001 (needs Docker and the root .env); the chat test calls the real AI
```

## Code

- `src/app/layout.tsx`: root layout, loads fonts (Space Grotesk for display, Manrope for body)
- `src/app/page.tsx`: client component handling sign-in only, with one `view` state (`checking`, `signed-out`, `failed`, `signed-in`). On load (and after signing in or registering, or on "Try again") it checks `/api/me`. Renders nothing while checking, `LoginForm` when signed out, an error with a "Try again" button if the server cannot be reached, and `Workspace` (keyed by username) when signed in
- `src/components/Workspace.tsx`: everything after sign-in. Header (app title, "Signed in as", Account and Log out buttons), `BoardBar`, the `AccountPanel` when "Account" is open, and the open board. Loads the board list and opens the board named in the URL (`?board=<id>`, kept up to date with `history.replaceState` so a reload stays on it) or the first one; shows "Loading board...", a load error with "Try again", an empty state when the user has no boards, or `KanbanBoard` keyed by board id (so switching boards starts with fresh board and chat state). Create, rename and delete (after `window.confirm`) call the API and reload the list; a failed action shows "That did not work..." and leaves the open board alone
- `src/components/BoardBar.tsx`: board switcher (`<select>` labelled "Board") and New board / Rename board / Delete board buttons. New and rename swap the bar for a name form ("New board name" or "Board name", required, up to 100 characters)
- `src/components/AccountPanel.tsx`: "Account settings" region with a change password form (current and new password; shows the result as a status message) and a delete account form (password, then `window.confirm`; calls `onDeleted` on success)
- `src/lib/api.ts`: fetch calls to the backend (same-origin cookie), with types from `api-types.ts`. Accounts: `getCurrentUser`, `login`, `register`, `logout`, `changePassword`, `deleteAccount` (each action returns null on success or a message for the user: the server's `detail` when it is a string, else a fallback such as `ACCOUNT_RULES` for a rejected username or password). Boards, which throw on failure: `listBoards`, `getBoard(id)` (returns `{id, name, version, board}`), `createBoard(name)`, `renameBoard(id, name)`, `deleteBoard(id)`. `saveBoard(id, board, version)` returns `saved` with the new version, `conflict` with the server's current board, or `error`. `sendChat(id, message, history)` returns `{reply, board, version}`, `board` null when the AI changed nothing; on failure it throws an `Error` whose message is for the user
- `src/components/LoginForm.tsx`: username / password form that signs in, or creates an account after "Create an account" (shows `ACCOUNT_RULES`; "Sign in" switches back). `onLogin` and `onRegister` resolve to null on success or a message to show (wrong credentials, the lockout message, a taken username)
- `src/app/globals.css`: Tailwind import and CSS variables for the color scheme (`--accent-yellow`, `--primary-blue`, `--secondary-purple`, `--navy-dark`, `--gray-text`), plus header styling (`--nav-chip` for the column name chips, `--logout` for the Log out button and overdue dates), priority dot colors (`--priority-high`, `--priority-medium`, `--priority-low`) and board styling (`--column-surface`, `--badge`, `--card-text`, `--add-card`, and one card color per column: `--card-backlog`, `--card-discovery`, `--card-progress`, `--card-review`, `--card-done`)
- `src/lib/kanban.ts`: types (`Card`, `Column`, `BoardData`, taken from the generated `api-types.ts`; `CardFields` is a card without its id; `Priority`, `priorities`), `columnColor(index)` (card background by column position, repeating after the five standard colors), `initialData` (5 columns, 8 sample cards; the backend holds the same default board, so this is only used by tests), pure board updates that return a new board (`moveCard` on columns; `renameColumn`, `addColumn` (at the end), `deleteColumn` (callers only delete empty columns), `moveColumn(board, id, offset)` (no change past either end), `addCard`, `editCard(board, id, fields)`, `deleteCard` on the board), `createId`; labels (`parseLabels` turns "a, b" into a trimmed, de-duplicated list within the backend's limits of 10 labels of 30 characters; `boardLabels`); dates (`localToday` as YYYY-MM-DD in the user's time zone, `isOverdue`); filters (`Filters`, `noFilters`, `hasFilters`, `matchesFilters`: text in the title, details or labels ignoring case, plus exact priority and label)
- `src/lib/api-types.ts`: generated by `npm run api:types` from `backend/openapi.json`; do not edit by hand. `kanban.ts` and `api.ts` take their types from it, so a backend model change that breaks the frontend shows up as a type error
- `src/components/KanbanBoard.tsx`: client component holding one board's state (starts from the `boardId`, `initialBoard` and `initialVersion` props). Shows the column name chips (a list labelled "Columns"), `BoardFilters` and the save notices above the columns. Columns sit in a row that shares the width and scrolls sideways when they do not fit (stacked below `lg`); `NewColumnForm` follows the last column. Filters live in state (not saved) and only change which cards each column shows; the last column's cards are never shown as overdue. Every change updates state and then queues a save (`persist`); column renames update state on each keystroke but save only on blur / Enter (`onRenameDone`). Saves run one at a time (`flush`), each sent with the version the previous save returned; changes made while a save is in flight are combined into the next save. A `409` conflict replaces the board with the server's (`replaceBoard`) and shows a notice; a failed save shows an error. Either notice clears after the next successful save. `DndContext` (given a `useId` id so server and client markup match), handlers for drag end, column rename, add, edit and delete card
- `src/components/ChatSidebar.tsx`: AI chat. Keeps the conversation in state (lost on reload or when switching boards) and sends it as `history` with each message to `/api/boards/{boardId}/chat`; shows "Thinking..." while waiting and the error message from `sendChat` if the request fails; passes the returned board and version to `onBoardUpdate` when the AI changed something. Can be hidden and shown. `KanbanBoard` renders it beside the board at `2xl` (1536px+) and full width below the board on smaller screens, and passes `replaceBoard` (the backend has already saved the AI's board, so it is not saved again)
- `src/components/BoardFilters.tsx`: search region "Filter cards" with "Search cards", "Filter by priority", "Filter by label" (only when the board has labels) and "Clear filters" (only when a filter is set)
- `src/components/CardForm.tsx`: the card form used for adding and editing: title (required), details, priority, due date (`<input type="date">`) and labels (comma separated); `emptyCard` is the blank starting point
- `src/components/KanbanColumn.tsx`: droppable column (yellow top border) with an uppercase editable title input (blur or Enter calls `onRenameDone`), a card count badge ("2/5" with the label "2 of 5 cards" while filtering), controls to move the column left or right and delete it ("Move Backlog column left", "Delete Backlog column"; disabled at the ends and while the column has cards; shown on hover like the card icons), the sortable list of matching cards ("No matching cards" when a filter hides them all), `NewCardForm`
- `src/components/KanbanCard.tsx`: sortable card colored by its column (`color` prop), with title, details, `CardMeta` (priority pill with a colored dot, "Due Dec 1, 2026" or a red "Overdue ..." when `overdue`, label pills; also used by the drag preview), and edit (pencil) and delete (X) icon buttons in the top-right corner. On devices with a mouse the icons and a yellow left edge appear on hover or keyboard focus (`pointer-fine:` variants); on touch screens the icons are always shown. Edit swaps in a `CardForm`; while editing, dragging is disabled and dnd-kit's `attributes` are not applied, so the form is not inside an `aria-disabled` "button"
- `src/components/KanbanCardPreview.tsx`: card shown in the drag overlay (same color and shared `cardClassName`)
- `src/components/NewColumnForm.tsx`: dashed "+ Add column" tile after the last column; opens a "New column title" form (required)
- `src/components/NewCardForm.tsx`: full-width blue "+ Add card" button that opens a `CardForm`

## Data shape

Generated from the backend's `Board` model (see `src/lib/api-types.ts`):

```ts
BoardData = {
  columns: { id: string; title: string; cardIds: string[] }[];
  cards: {
    [key: string]: {
      id: string; title: string; details: string;
      priority?: "low" | "medium" | "high" | null; dueDate?: string | null; labels: string[];
    };
  };
}
```

New cards without details get an empty string, the same as cards the AI creates. Columns can be added, renamed, moved left or right and deleted when empty; the last column counts as finished. Card order is the order of `cardIds`.

The fake `fetch` behaves like the backend (a save based on version n returns n + 1). Card fields: shown on the card, overdue (not in the last column), add and edit (and clear) priority, due date and labels, search, priority and label filters with counts and "Clear filters". - `src/app/page.test.tsx`: sign-in flow against the fake server (signed out, already signed in, valid and invalid credentials, lockout message, create an account, taken username, rules shown for a rejected username, switching between the forms, log out, delete account); a board list failure and an unreachable server each show an error with "Try again" that recovers
- `src/components/Workspace.test.tsx`: against the fake server: opens the first board and puts it in the URL, opens the board in the URL (or the first one if it is not there), creates (not with an empty name), switches, renames and deletes boards (confirm and cancel), the empty state after deleting the last board, changes are saved to the open board only, a failed action shows a message; account settings: change password (and wrong current password), delete account refused with a wrong password or without confirming, close
- `tests/kanban.spec.ts`: Playwright e2e (signs in and resets the board first) for load, add card, drag a card between columns, edit card, rename column, every change kept after reload, priority / due date / labels added, shown as overdue, filtered by label, text and priority and kept after reload, a stale second tab gets a `409` and loads the latest board instead of overwriting it, no console errors on load
- `tests/chat.spec.ts`: an AI failure (the `/api/chat` response replaced with a 502 using `page.route`) shows the server's message; then a real AI call through the container: asks it to create a card and move it to Done, checks the card appears in Done without a reload and is still there after one
- `tests/auth.spec.ts`: Playwright e2e for login form, bad credentials, sign in, reload keeps session, log out, a board list that fails to load once (via `page.route`) shows "Try again" and recovers, 401 from `/api/me`; create an account and sign back in, a taken username, change password, delete account, another user's board id in the URL is not opened
- `tests/columns.spec.ts`: each test registers its own account. Add a column and a card in it, move it, delete an emptied column, reload; a column with cards cannot be deleted; many columns scroll sideways and a card can be dragged to the last one. `toHaveValues` is for multi-selects, so column titles are read with `evaluateAll` and `expect.poll`
- `tests/boards.spec.ts`: each test registers its own new account. Create a board (cards kept separate, reload stays on it), switch, rename, delete (confirm and cancel), empty workspace, and the chat request goes to the open board
- `tests/helpers.ts`: `signIn(page, password?, username?)`, `registerNewUser(page)` (a unique account, left signed in; returns the username), `resetBoard(page)` (leaves the signed-in user with one board, "My first board", holding `initialData`), `saved(page, action)` (waits for the board save an action triggers)
- Playwright's `getByLabel` matches substrings case-insensitively, so use `{ exact: true }` for "Message" (otherwise it also matches the "Chat messages" log)
- `tests/global-setup.ts`: Playwright global setup. Builds the `pm` image from the current code, removes any leftover `pm-test` container, starts a new one on port 8001 (no volume, so each run starts with an empty database; `--env-file .env` for the live chat test), waits for `/api/health`, and removes the container after the run. The real `pm` container and its `pm-data` volume are never touched
- Playwright runs with `workers: 1` because the kanban and chat tests share the boards of `user` in the test container (tests that need their own boards register a new account instead)
- On Windows, run Vitest from a path with an uppercase drive letter (`C:\...`, which PowerShell and cmd give you). Git Bash's `/c/...` gives Node a lowercase `c:\`, Vitest is then loaded twice, and the global `expect` lacks the jest-dom matchers ("Invalid Chai property")
- Next.js renders a hidden route announcer with `role="alert"`, so in e2e tests find messages by text, not by the alert role
- Vitest setup: `src/test/setup.ts` imports `@testing-library/jest-dom/vitest`; `src/test/vitest.d.ts` references the Vitest globals and jest-dom matcher types
