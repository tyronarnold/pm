# Backend

Python 3.15, FastAPI, served by uvicorn on port 8000 inside the Docker container. Dependencies are managed with uv (`pyproject.toml`, `uv.lock`).

## Code

- `app/main.py`: creates the FastAPI app: Starlette `SessionMiddleware` (signed `session` cookie holding the user id and session version, `same_site=lax`; secret and Secure flag from `auth`), `GET /api/health`, the routers from `app/routes/`, and `static/` mounted at `/` last so the `/api` routes take priority. On startup (lifespan) it creates or upgrades the database, creates the demo `user` / `password` account if missing, and makes it an admin if nobody is one.
- `app/access.py`: who may do what. `current_user` (`CurrentUser` annotation) loads the user from the database on every request and returns 401 when not signed in, the account no longer exists, or the session's version is older than the user's (the password was changed elsewhere); use it on every protected route. `current_admin` (`CurrentAdmin`) adds 403 for non-admins. `find_board` returns a board the user owns or is a member of, or raises 404; `find_owned_board` also raises 403 for a member (owner-only actions). `NOT_FOUND` / `OWNER_ONLY` describe those responses in the OpenAPI schema.
- `app/routes/`: the API routes, one `APIRouter` per area, included by `main.py`. `accounts.py`: register, login, logout, `/me`, password, account deletion, and `create_account` (a user with a first board of sample cards, whose creation is logged; also used at startup). `admin.py`: the `/api/admin/users` routes. `boards.py`: board list, create, get, rename, delete and save, members, activity, and `summary` / `detail` (the response shapes); saves record activity through `describe_changes`, and create, rename, share, remove and leave as fixed sentences. `chat.py`: the AI chat (uses `boards.detail`).
- Board summaries include `board_stats` (`cards`, `done` = cards in the last column, `overdue` = due before the server's date and not in the last column)
- `app/auth.py`: argon2id password hashing (`hash_password`, `verify_password`; an unknown user is checked against a dummy hash so it takes as long as a wrong password). `session_secret()` reads `SESSION_SECRET` (random fallback with a warning: restarts then sign everyone out); `https_only()` reads `SESSION_HTTPS_ONLY=true`. Login rate limiting in memory: 5 failures for a username within 15 minutes lock that username until the oldest failure expires (`is_locked_out`, `record_failure`, `clear_failures`; keyed by username because behind Docker every client has the same address)
- `app/db.py`: SQLite with the built-in `sqlite3` module. File at `DB_PATH` (default `/app/data/pm.db`, the `pm-data` volume). `init_db` creates the tables and upgrades older databases (adds missing columns such as `users.session_version`; rebuilds `users` with `AUTOINCREMENT` ids so a deleted user's id is never reused; rebuilds the one-board-per-user `boards` table). Users: `create_user` (None if the name is taken), `ensure_password`, `get_user`, `find_user` (user and hash by name), `get_password_hash`, `set_password_hash` (also increments `session_version` and returns it), `delete_user` (cascades to boards and memberships). Activity: `add_activity(board_id, username, messages, via_ai)` (keeps the newest `ACTIVITY_KEPT` = 200 per board), `list_activity(board_id, limit)` (newest first, `Activity` rows). Administration: `list_users` (`UserSummary`: username, is_admin, created_at, boards owned), `set_admin`, `count_admins`, `ensure_an_admin(username)` (makes the user an admin only if nobody is one). Boards: `list_boards`, `get_board` and `update_board(user_id, board_id, data, version)` (saves only if the board is still at `version`; returns the new version or None) work for the owner and members (`ACCESS`); `create_board`, `rename_board(owner_id, ...)` and `delete_board(owner_id, ...)` for the owner. Members: `list_members` (usernames in the order added), `add_member` (False if already a member), `remove_member`. Rows come back as `User` and `BoardRow` named tuples; `BoardRow.owner` is the owner's username. See `docs/DATABASE.md`.
- `app/board.py`: Pydantic `Board` / `Column` / `Card` models (matches `docs/board.schema.json`; a card's `priority`, `dueDate` and `labels` are optional with defaults, so boards stored before them still load; also checks every card is in exactly one column, card keys match ids, and column ids are unique and differ from card ids), `describe_changes(old, new)` (the activity sentences for a change: columns added, renamed, deleted or reordered, then cards added, moved, edited or deleted, then cards reordered within a column), `board_stats(board, today, username)` (also counts `mine`: the user's assigned cards not in the last column), `DEFAULT_BOARD` (the sample cards a new account starts with), `EMPTY_BOARD` (the same columns, no cards; for new boards), `column_ids`. `Operation` (`create_card` / `edit_card` / `move_card` / `delete_card`; unused fields are null; `priority`, `due_date`, `labels` and `assignee` set those card fields on create and edit, null meaning unchanged, `labels` replacing the whole list and an empty `assignee` unassigning) and `apply_operations(board, operations, people)`: returns `Applied(board, skipped)`, a new board with the operations applied in order (`_apply` does one) plus the operations it skipped (unknown card or column ids, an edit that changes nothing, a card that would fail validation: no title, a bad date, too many or too long labels, a column without a title, or deleting a column that still has cards, or assigning someone not in `people`, the usernames with access). Column operations: `create_column` (temporary `column_id` mapped like a new card's, `title`, `position`), `rename_column`, `delete_column` (empty columns only). New and edited cards are built with `Card.model_validate`, so the AI's values get the same checks as a saved board. New cards get a `card-<random>` id; the temporary `card_id` the AI gives in `create_card` maps to that id for later operations in the same list, so the AI can create a card and then move or edit it in one reply. `position` null means bottom of the column.
- `app/ai.py`: OpenRouter via the `openai` SDK (`base_url` https://openrouter.ai/api/v1, key from `OPENROUTER_API_KEY`), model `anthropic/claude-haiku-5.5` with OpenRouter's `reasoning: {"effort": "low"}` (passed in `extra_body`). `ask(messages)` returns plain reply text. `chat(board, people, history, message)` sends `SYSTEM_PROMPT`, today's date, the people on the board and the board JSON (second system message, `build_messages`; the date lets the AI turn "next Friday" into a due date), the history and the new message, and uses Structured Outputs (`chat.completions.parse` with `response_format=ChatResult`) to get `{reply, operations}`. Failures (timeout, connection or HTTP errors, a reply cut off, or a refusal) are logged and raised as `AIError`, whose message is written for the user. The client has a 30 second timeout (`TIMEOUT_SECONDS`) and retries once. `client()` is created per call, so tests replace it with a fake.
- `app/openapi.py`: `schema()` returns the app's OpenAPI schema; `python -m app.openapi <path>` writes it to a file. `openapi.json` (committed) is the saved copy the frontend's TypeScript types are generated from; `tests/test_openapi.py` fails when it is out of date. After changing a Pydantic model or route, run `npm run api:types` in `frontend/` and commit both generated files
- `static/`: not in the repo. The Docker build copies the frontend's static export (`frontend/out`) here, so the app only runs inside the container.
- `tests/`: pytest tests using FastAPI's `TestClient`. `conftest.py` points `DB_PATH` at a temporary file for every test and provides the `client`, `signed_in` (demo user) and `board_id` (the demo user's first board) fixtures and the `login` / `register` helpers. Use `with TestClient(app) as client` for a second session (another user, or the same user elsewhere), so the startup code runs. `test_accounts.py` covers registration, password changes and account deletion; `test_board.py` the board routes, ownership and database upgrades; `test_sharing.py` sharing (members read, save and chat; owner-only actions; removing and leaving; cascades on deletion); `test_activity.py` the activity log (`describe_changes`, `board_stats`, what each route records, members and AI changes, limits); `test_admin.py` administration (admin-only routes, roles and the last admin, password resets, deleting users, the startup admin rule). Tests that call OpenRouter are marked `live` and skipped when `OPENROUTER_API_KEY` is not set; all other AI tests use the `fake_ai` fixture in `conftest.py` (`FakeClient` records requests and answers `parse` with a fixed result and `create` with fixed text). Coverage settings are in `pyproject.toml` (`[tool.coverage.*]`: the `app` package, branches, `fail_under = 98`, the `__main__` block excluded); `--cov` takes an optional argument, so put it after any test paths. `filterwarnings` turns `ResourceWarning` (and the unraisable-exception warning it causes in `__del__`) into failures, so a connection left open fails the run.

## Routes

Accounts:
- `GET /api/health`: returns `{"status": "ok"}`
- `POST /api/register` `{username, password}`: creates the account (username 3-32 of `a-z 0-9 . _ -`, password at least 8 characters; 422 otherwise) with a first board of sample cards, signs in and returns `{username}` (201); 409 if the username is taken
- `POST /api/login` `{username, password}`: checks the password against the stored argon2 hash (the demo account is `user` / `password`); sets the session, returns `{username}`; 401 on bad credentials; 429 after 5 failed attempts for that username within 15 minutes (each `detail` is a message for the user)
- `POST /api/logout`: clears the session
- `GET /api/me`: returns `{username, is_admin}`; 401 when signed out (register and login return the same shape)
- `PUT /api/me/password` `{current_password, new_password}`: changes the password and signs out every other session of the account (this one stays signed in); 403 if the current password is wrong
- `DELETE /api/me` `{password}`: deletes the account and its boards and signs out (204); 403 if the password is wrong. Other sessions of that account get 401 from then on

Administration (all 401 when signed out, 403 "Only admins can do that." for non-admins, 404 for an unknown username):
- `GET /api/admin/users`: every user, sorted by username, as `[{username, is_admin, created_at, boards}]` (`boards` = boards they own)
- `PATCH /api/admin/users/{username}` `{is_admin}`: make the user an admin or not; returns the user; 409 if it would remove the last admin. Takes effect on the user's next request
- `PUT /api/admin/users/{username}/password` `{new_password}` (at least 8 characters): sets the password, signs the user out everywhere (session version) and lifts a sign-in lockout; an admin resetting their own password stays signed in
- `DELETE /api/admin/users/{username}`: deletes the user, their boards and memberships (204); 409 for yourself (use `DELETE /api/me`)

Boards (all 401 when signed out, 404 for a board that does not exist or is not shared with you, 403 when a member tries an owner-only action):
- `GET /api/boards`: the boards the user owns or is a member of, oldest first, as `[{id, name, updated_at, owner, cards, done, overdue, mine}]` (`owner` is a username; `done` counts cards in the last column, `overdue` cards past their due date by the server's date and not in the last column, `mine` the signed-in user's assigned cards not in the last column)
- `GET /api/boards/{id}/activity`: the board's latest 50 changes, newest first, as `[{username, message, via_ai, created_at}]` (owner and members)
- `POST /api/boards` `{name}`: creates a board with the standard columns and no cards; returns `{id, name, owner, version, board}` (201). Names are trimmed and must be 1-100 characters
- `GET /api/boards/{id}`: returns `{id, name, owner, members, version, board}` (owner and members; `members` lists usernames, not the owner)
- `PATCH /api/boards/{id}` `{name}`: renames the board (owner only; does not change its version); returns `{id, name, updated_at, owner}`
- `DELETE /api/boards/{id}`: deletes the board and its memberships (owner only, 204)
- `GET /api/boards/{id}/members`: usernames the board is shared with, in the order added (owner and members)
- `POST /api/boards/{id}/members` `{username}` (trimmed, lowercased): shares the board (owner only); returns the members (201). 422 if there is no such user, 409 if already a member or the owner
- `DELETE /api/boards/{id}/members/{username}`: the owner removes a member, or a member removes themselves (leaves); 204, 404 if not a member, 403 for a member removing someone else
- `PUT /api/boards/{id}` `{version, board}` (owner and members): validates and saves the whole board if it is still at `version`, returns `{version, board}` with the new version; 409 with the current `{version, board}` if it changed since; 422 if invalid (columns may be added, renamed, reordered or removed, but column ids must be unique and differ from card ids, and every card must stay in exactly one column)
- `POST /api/boards/{id}/chat` `{message, history}` (history: list of `{role: "user" | "assistant", content}`): asks the AI about that board, then applies the returned operations to its latest saved version (the user may have saved while the AI was working) and saves it if it changed; returns `{reply, board, version}` with `board` null when nothing changed. If some operations were skipped, a note saying how many is appended to `reply` (so the user, and the AI through the history, know). 502 with a user-facing `detail` when the AI call fails; 409 if the board changed again during that final save

## Commands

Tests run inside the container image (built by `scripts/start.*` or `docker build -t pm .`):

```
docker run --rm pm uv run --no-sync pytest                          live tests skipped
docker run --rm --env-file .env pm uv run --no-sync pytest          all tests, including live
docker run --rm --env-file .env pm uv run --no-sync pytest -m live  live tests only
docker run --rm pm uv run --no-sync pytest --cov                    with line and branch coverage; fails below 98%
```

uv is not installed on the host. To change dependencies, run uv in a container from the repo root:

```
docker run --rm -v "$PWD/backend:/work" -w /work ghcr.io/astral-sh/uv:0.13.9-python3.15-trixie-slim uv add <package>
```
